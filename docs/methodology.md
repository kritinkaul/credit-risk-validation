# Planned modeling methodology

No dataset or empirical experiment exists yet. This protocol will be revised with
explicit reasoning once the [data contract](data_contract.md) can be completed.

## Target, information set, and leakage

For an eligible record at prediction timestamp t, estimate the probability of a
specified default event in (t, t + H], where both the event and H remain undecided.
Specify whether existing defaults are excluded, the unit of observation, and how
multiple loans per borrower are handled. The horizon must reflect the eventual
research question and observable follow-up, rather than an arbitrary default.

A negative label needs full follow-up through the horizon plus any reporting lag.
Records without mature outcomes are unresolved, not nondefaults; document exclusion
and resulting selection bias. Define label availability separately from event time.
Reconcile restructurings, prepayments, missing outcomes, and competing account events
before treating this as a binary task. No survival model is in scope.

Features must have been available at t, accounting for publication/reporting delays
and revisions. Exclude collections activity, later balances/statuses, post-default
recovery information, and outcome-derived fields. Audit joins for future information,
duplicated records, and changing record grain. An old event timestamp does not prove
that a value was available at prediction time.

## Splits and estimation

When suitable dates exist, order training, validation/calibration, and final test
cohorts chronologically. At each simulated model-fit date, training outcomes must
already be mature. Use gaps or purging where label windows/availability would leak
across boundaries. Choose dates only after assessing coverage and event counts;
do not hard-code split fractions before seeing the data.

Repeated borrowers violate row independence. Define whether the estimand concerns
new borrowers or future observations of existing borrowers. For new-borrower
evaluation, keep borrower groups disjoint across splits, potentially excluding
borrowers spanning time boundaries and disclosing the population change. If the
use case permits existing borrowers, preserve chronology, prohibit future history
and labels, report overlap, and account for clustered dependence. Do not apply
row-wise random splitting as a substitute for this decision.

Fit imputers, encoders, scalers, feature selection, and all learned transformations
on each training fold only. Use pipelines to apply them unchanged downstream.
Tune with rolling/expanding temporal folds and appropriate borrower restrictions;
ordinary shuffled cross-validation can mix future and past. If dates are absent,
use a justified grouped design and explicitly state that out-of-time performance
cannot be measured. If identifiers are absent, disclose that borrower leakage
cannot be fully ruled out.

Keep a final test set untouched until the model, calibration choice, metrics, and
analysis protocol are frozen. Repeated test-driven tuning makes it a validation
set and invalidates its role as an unbiased final assessment. Log every exposure;
new hypotheses generated by test findings need fresh evidence.

## Baseline, challenger, and calibration

Begin with regularized logistic regression: an interpretable baseline with linear
log-odds under the chosen feature representation. Check functional-form assumptions,
collinearity, scaling and sparse categories. Coefficients are conditional associations,
not causal effects. An intercept-only prevalence baseline will contextualize losses.

Use LightGBM as a nonlinear challenger for interactions and nonlinearities. Compare
on identical eligible cohorts and feature availability, with documented tuning
budgets. Added complexity is justified only by evidence, not assumed superiority.

Class weighting or resampling changes the fitting objective and effective class
prior, potentially improving ranking while distorting population probabilities.
Document it, compare an unweighted baseline, and assess calibration on data with
the intended prevalence. Calibration does not guarantee transport to a new population.

Fit candidate sigmoid/isotonic calibration only with held-out validation predictions
or appropriately cross-fitted predictions, never with in-sample training predictions
or test labels. Separate model selection from calibrator fitting where sample size
permits; otherwise use a documented nested/cross-fitting design. Preserve time order.
Isotonic flexibility can overfit small samples; choose based on available evidence.
Report uncalibrated and calibrated results and avoid assuming calibration always helps.

## Evaluation and interpretation

ROC-AUC measures ranking across thresholds; PR-AUC emphasizes precision/recall for
the default class and depends strongly on event prevalence. Predeclare whether
PR-AUC means average precision or trapezoidal integration; they are not identical.
Report prevalence and cohort event counts alongside both metrics.

Brier score is mean squared probability error; log loss penalizes confidently wrong
predictions strongly. Both assess probability quality and reflect more than calibration
alone. Calibration plots compare predicted probabilities with observed frequencies;
show bin counts and uncertainty and assess sensitivity to binning. Disclose numerical
clipping for log loss. Neither one plot nor one score establishes universal reliability.
Accuracy alone can look high by predicting the majority class for every borrower.
Any threshold analysis must disclose costs/constraints and choose thresholds without
test tuning; no lending threshold is proposed here.

Feature importance, coefficients, or future explanation plots describe fitted model
behavior, not causal mechanisms. Correlated features can make explanations unstable.
Subgroup comparisons require adequate sample sizes and lawful access to relevant
attributes; omission of sensitive attributes does not by itself establish fairness.
